# Shikshly v1.4 Production Status

## Scope

Version 1.4 is a security/build-hardening release based on the validated v1.3 codebase. Functional application behaviour is intentionally preserved.

## Changes

1. Website build migrated from Tailwind CSS 3.4.x to Tailwind CSS 4.3.x with the official Vite plugin.
2. Existing Tailwind JavaScript theme is loaded explicitly with `@config` for backward-compatible styling.
3. Old Tailwind/PostCSS configuration was removed.
4. `shell-quote` is pinned through npm overrides to the current 1.12.x release line.
5. Node.js baseline is 22.13+.
6. Added `npm run security:audit` for runtime dependencies and `npm run security:full` for the complete dependency tree.
7. Documented upstream-only vulnerabilities with no compatible patched release instead of forcing breaking downgrades.

## Security caveat

As of 2026-10-07, public advisories report no patched release for `braces` CVE-2026-93687 and no patched npm release for `node-forge` CVE-2026-85393. These are transitive Expo/Metro tooling dependencies. They are not silently marked as fixed.

The `node-forge` advisory concerns RSA PKCS#1 v1.5 signature verification. Shikshly's server authentication uses Node's native JWT/bcrypt stack, not node-forge. Expo/Metro remains a separate mobile build-tool dependency and must be upgraded when Expo ships a compatible fix.

## Release gate

Before production deployment, run `npm install`, `npm run verify`, `npm run security:audit`, `npm run security:full`, and a real MongoDB/transaction smoke test. External providers (Razorpay, MSG91, email), production secrets, HTTPS, backups, monitoring, legal pages, and store signing still require real production configuration.

## Lockfile note

This archive intentionally retains the v1.3 lockfile as a historical baseline while the Tailwind v4 migration changes the dependency graph. Run `npm install` once after extraction to regenerate `package-lock.json` for the v1.4 manifests; then commit that generated lockfile and use `npm ci` in CI/deployment. The source package does not claim that an unregenerated lockfile is a valid frozen v1.4 install.
